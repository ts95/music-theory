# Étude definitions, per content version

## Purpose

This file is the reference for **interpreting versioned practice history**. Every SRS record now stores
the étude `version` that was active when it was answered, and the CSV export surfaces that `version`
column. Because an étude's questions — and what each difficulty *level* scopes — can change over time, a
difficulty "level" recorded long ago may not mean the same thing today. This document pins down what each
étude (and each of its levels) actually *was* at every version, so old data stays interpretable.

## How `Etude.version` works

- `Etude.version` is an optional field on each étude in **`src/questions/etudes.ts`** (typed in
  `src/contracts.ts`). It **defaults to `1`** when omitted.
- **Bump it whenever an étude's questions or difficulty change** — new question material, changed level
  scopes, changed distractors, changed timing, etc.
- The active version is recorded alongside each answered question, so historical accuracy/practice data
  can be read against the definition that was live at the time.

**Every étude is currently version 1.** (No `version` is set in `src/questions/etudes.ts`, so all default
to `1`.)

All questions are generated deterministically (no RNG — SRS ids must stay stable) in
**`src/questions/generators.ts`**; explanations come from `src/questions/explanations.ts`. The 12 keys
live in `src/theory/keys.ts` (circle-of-fifths order from C): C, G, D, A, E, B, F♯, F, B♭, E♭, A♭, D♭,
each with its relative minor.

Sudden-death answer timers are applied per **category** in `src/components/ReviewSession.tsx`
(`TIMED_LIMITS`); a question may override with its own `timeLimitMs`. Categories absent from that map are
untimed.

## No. 1 — Relative Minors (`relative-minors`) — current version: 1

### v1

- **Question family:** Relationship recall — "What is the relative minor of *X* major?", one question per
  key (12 total). Generated by `relativeMinorQuestions()` in `src/questions/generators.ts`.
- **Levels:** none (no `levels`; single undifferentiated set).
- **Distractors:** the relative-minor names of every *other* key (the answer plus three other minor
  names; `buildQuestion` sorts choices and keeps the first three distinct distractors).
- **Audio:** each minor-name choice plays its tonic minor triad (hover-to-play).
- **Reveal:** highlights the major/relative-minor pair on the **circle of fifths** (`q.circle`).
- **Timing:** category `Relative minor` — **5 s** sudden-death (`TIMED_LIMITS` in `ReviewSession.tsx`).

## No. 2 — Scales (`scales`) — current version: 1

### v1

- **Question family:** Scale spelling — "What are the notes of the *X* natural / harmonic / melodic minor
  scale?", one question per (key, scale type) = 12 keys × 3 forms = 36. Generated by
  `scaleSpellingQuestions()` in `src/questions/generators.ts`; spellings computed in `src/theory/scales.ts`.
- **Levels:** none.
- **Distractors:** all options start on the **same tonic** so the first note never reveals the answer.
  Candidates are the two sibling minor forms plus three other same-tonic scales — the parallel **major**,
  **Dorian**, and **Phrygian**. The mix is varied deterministically per question (alternating "2 siblings
  + 1 other" vs "1 sibling + 2 others", rotating which appear), keyed by `keyIndex + typeIndex`.
- **Audio:** each scale choice plays ascending (hover-to-play).
- **Reveal:** lights the answer scale on the piano keyboard, each key labelled with RH over LH fingerings
  (from `src/theory/fingerings.ts`; the same finger sequence is shared across the three minor forms).
- **Timing:** untimed (no `Scale spelling` entry in `TIMED_LIMITS`).

## No. 3 — Play the Scale (`scale-play`) — current version: 1

### v1

- **Question family:** Interactive — the student is given a key and **plays the scale ascending** on the
  on-screen keyboard or a connected MIDI keyboard; matched positionally by pitch class. Not multiple
  choice (`q.scalePlay`, no `choices`). Generated by `scalePlayQuestions()` in
  `src/questions/generators.ts`; fingerings from `src/theory/fingerings.ts`.
- **Levels** (`['Easy','Medium','Hard']`, `SCALE_PLAY_LEVELS`): cumulative ABRSM-style key scope; each
  in-scope **minor** key appears in all three forms (natural / harmonic / melodic).
  - **Easy (L1):** 1 octave, **15 s** budget. Majors C, G, D, F; minors A, D.
  - **Medium (L2):** 2 octaves, **20 s** budget. Majors C, G, D, F, A; minors A, D, E, G.
  - **Hard (L3):** 2 octaves, **15 s** budget. **All 12** majors and **all 12** minors.
- **Distractors:** none (interactive; graded pass/fail by what the student plays).
- **Timing:** sudden-death budget is per-level (`seconds` above), enforced on the interactive card, not
  via `TIMED_LIMITS`.

## No. 4 — Chords by Degree (`chords`) — current version: 1

### v1

- **Question family:** Diatonic chord recall — "In *key*, what is the *roman* chord?" for both modes of
  every key. Degrees are the trimmed set I/i, ii/ii°, IV/iv, V, vi/VI, vii° (`CHORD_DEGREES = [0,1,3,4,5,6]`)
  plus the **V7**. Generated by `chordDegreeQuestions()` in `src/questions/generators.ts`; chords built
  in `src/theory/chords.ts`. Minor V and vii° borrow the harmonic minor's raised 7th (clarified in the
  reveal caption).
- **Levels** (`['Easy','Medium','Hard']`): cumulative by key-signature accidentals
  (`CHORD_LEVEL_ACCIDENTALS = [1, 3, 12]`):
  - **Easy (L1):** keys with ≤1 accidental (C/G/F + relative minors).
  - **Medium (L2):** keys with ≤3 accidentals.
  - **Hard (L3):** all 12 keys.
- **Distractors:** a **same-root / different-quality** chord (so the root alone never reveals it), plus
  the **same degree in other keys of the same mode** (so the quality alone never reveals it).
- **Audio:** each chord choice plays as a block (hover-to-play).
- **Reveal:** lights the answer chord (root position) on the keyboard with RH/LH fingerings.
- **Timing:** category `Diatonic chord` — **5 s** sudden-death.

## No. 5 — Chord Recognition (`chord-recognition`) — current version: 1

### v1

- **Question family:** Read a diatonic chord rendered on a **staff** (under its key signature) and name
  it as a chord symbol, with slash notation for inversions — "In *key*, name the chord shown." Both modes,
  all seven degrees. Minor uses harmonic forms at III/V/vii° (so augmented III+, dominant V, diminished
  vii° appear). Generated by `chordRecognitionQuestions()` in `src/questions/generators.ts`. Size,
  inversion, and clef (treble/bass) are chosen deterministically from a running index for a stable,
  well-mixed bank; an "unclean" ninth is demoted to its seventh.
- **Levels** (`['Easy','Medium','Hard']`, `REC_LEVELS`): scale chord complexity **and** key range:
  - **Easy (L1):** triads only, no inversions, keys with ≤1 accidental.
  - **Medium (L2):** triads + sevenths, inversions allowed, keys with ≤3 accidentals.
  - **Hard (L3):** triads + sevenths + ninths, inversions allowed, all 12 keys.
- **Distractors:** prioritized to vary inversion / root / quality — the other inversions of the same chord
  (when inversions are on), the **same degree/size in neighbour keys** (different roots), and a
  **same-root / alternate-quality** symbol. Easy (no inversions) keeps root-position symbols only.
- **Audio:** each choice sounds its own chord as a block, voiced in a comfortable register (hover-to-play).
- **Reveal:** the chord is shown on the staff as the *question* itself (`q.notation`, not on-reveal).
- **Timing:** category `Chord recognition` — **10 s** sudden-death; inversion questions override to
  **15 s** (`q.timeLimitMs`, +5 s to re-stack the notes in thirds).

## No. 6 — Progressions (`progressions`) — current version: 1

### v1

- **Question family:** Spell a Roman-numeral progression in concrete chords — "In *key*, spell the
  progression *label*." Generated by `progressionQuestions()` in `src/questions/generators.ts` from a
  curated set (`PROGRESSIONS`). Triad form for every progression across every key of its mode; a seventh
  form is added only for the idiomatic **ii–V–I** / **ii°–V–i** (`SEVENTH_PROGRESSION_SLUGS`).
  - **Major progressions:** I–IV–V, ii–V–I, I–V–vi–IV, I–vi–IV–V, vi–IV–I–V, I–IV–vi–V.
  - **Minor progressions:** i–iv–V, ii°–V–i, i–VI–iv–V, VI–iv–i–V, i–iv–V–i.
- **Levels** (`['Easy','Medium','Hard']`): cumulative by key-signature accidentals
  (`PROGRESSION_LEVEL_ACCIDENTALS = [1, 3, 12]`):
  - **Easy (L1):** keys with ≤1 accidental (C/G/F + relative minors).
  - **Medium (L2):** keys with ≤3 accidentals.
  - **Hard (L3):** all 12 keys.
- **Distractors:** a **same-key variant that keeps the first chord** but alters the last (so "starts on
  the tonic chord" is no longer a giveaway), plus the **same progression transposed to other keys** of
  the same mode.
- **Audio:** each progression choice plays as block chords in series (hover-to-play).
- **Reveal:** the chords are drawn on a treble staff under the key's signature (`q.notation`, on reveal).
- **Timing:** category `Progression` — **15 s** sudden-death.

## No. 7 — Intervals by Ear (`intervals-ear`) — current version: 1

### v1

- **Question family:** Hear an **ascending** interval and name it (relative-pitch training — the lower
  note is randomized each presentation; only the relationship is stored in `q.ear`). The 12 intervals
  within an octave (m2 … octave). Generated by `intervalEarQuestions()` in `src/questions/generators.ts`.
- **Levels** (`['Easy','Medium','Hard']`, `INTERVAL_LEVELS`): cumulative interval pool, widening choices:
  - **Easy (L1):** m2, tritone, P5, octave — **4 choices** (3 distractors).
  - **Medium (L2):** adds M2, m3, M3, P4 (8 intervals) — **5 choices** (4 distractors).
  - **Hard (L3):** all 12 intervals — **6 choices** (5 distractors).
- **Distractors:** the **nearest intervals by semitone** within the level's pool.
- **Audio:** owned by the question (`q.ear`, `kind: 'interval'`); no hover audio.
- **Timing:** untimed (no `Interval` entry in `TIMED_LIMITS`).

## No. 8 — Progressions by Ear (`progressions-ear`) — current version: 1

### v1

- **Question family:** Hear a progression played over its tonic and name it in Roman numerals. One
  question per curated progression (the same `PROGRESSIONS` set as No. 6 — 11 total: 6 major + 5 minor).
  Generated by `progressionEarQuestions()` in `src/questions/generators.ts`.
- **Levels:** none.
- **Distractors:** the other progressions **of the same mode**.
- **Audio:** owned by the question (`q.ear`, `kind: 'progression'`); each carries a short style/genre
  caption (`PROGRESSION_STYLE`) shown on reveal.
- **Timing:** untimed.

## No. 9 — Melodic Dictation (`melodic-dictation`) — current version: 1

### v1

- **Question family:** Hear a short diatonic motif over its tonic and name it in **solfège**
  (relative-pitch; root randomized per presentation). Motifs are 0-based scale degrees (0 = tonic …
  7 = octave) over both modes (`MELODY_LEVELS`). Generated by `melodicDictationQuestions()` in
  `src/questions/generators.ts`; solfège from `src/theory` (`solfege`).
- **Levels** (`['Easy','Medium','Hard']`):
  - **Easy (L1):** 3-note motifs (stepwise / triadic) — 10 patterns × 2 modes.
  - **Medium (L2):** 4–5-note motifs with leaps — 12 patterns × 2 modes.
  - **Hard (L3):** 5–8-note lines, including the complete ascending/descending scale — 10 patterns × 2 modes.
- **Distractors:** confusable degree-sequences — nudge a note by a step or swap two adjacent notes
  (`melodyVariants`); choices are the resulting solfège strings.
- **Audio:** owned by the question (`q.ear`, `kind: 'melody'`).
- **Timing:** untimed. (Note: sampling an individual scale note during playback counts as wrong — see the
  card behavior; not a category timer.)

## No. 10 — Rhythm Dictation (`rhythm-dictation`) — current version: 1

### v1

- **Question family:** Hear a one-bar rhythm and pick the matching **notation** (choices render as rhythm
  notation via `q.rhythmChoices`, not text). Generated by `rhythmDictationQuestions()` in
  `src/questions/generators.ts`. Each pattern sums to its metre's beats.
- **Levels** (`['Easy','Medium','Hard']`, `RHYTHM_LEVELS`): vocabulary, syncopation, metres, and tempo
  grow per level:
  - **Easy (L1):** tempo **76**. Simple metres only — 4/4, 3/4, 2/4. Whole/half/quarter/eighth durations
    + simple rests; little syncopation.
  - **Medium (L2):** tempo **100**. Metres 4/4, 3/4, **6/8**, 2/4, **12/8**, **2/2**. Adds sixteenth cells
    (ti-tika / tika-ti), dotted-eighth figures and the Scotch snap, eighth triplets, the tresillo, a tie,
    and off-beat eighths.
  - **Hard (L3):** tempo **138**. Metres 4/4, 3/4, 6/8, 2/4, 12/8, **5/4**, 2/2. Adds sixteenth runs,
    paired dotted-eighth/snap cells, tresillo and Charleston-style syncopation, tied off-beats, triplet
    beats, and a 32nd run.
- **Distractors:** other patterns in the **same level and metre**, chosen by closest onset (note) count.
- **Audio:** owned by the question (`q.ear`, `kind: 'rhythm'`, carrying meter, tempo, and pattern).
- **Timing:** untimed.

## Updating this file

This file is **append-only**. When you change an étude's questions or difficulty:

1. **Bump its `version`** in `src/questions/etudes.ts` (e.g. add/raise `version: 2` on that étude entry).
2. **Append a new subsection** under that étude here:

   ```
   ### vN — <YYYY-MM-DD>: <one-line summary of what changed>
   ```

   Describe the new version the same way the existing subsections do (question family, level scopes,
   distractors, timing).

3. **Leave all prior `### vN` subsections intact.** Old practice/CSV data was recorded against those
   definitions and must stay interpretable — never edit or delete a past version, only add the next one.
4. Update the étude's heading "current version: N" to match the bump.
