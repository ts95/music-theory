# Étude definitions, per content version

## Purpose

This file is the reference for **interpreting versioned practice history**. Every SRS record now stores
the étude `version` that was active when it was answered, and the CSV export surfaces that `version`
column. Because an étude's questions — and what each difficulty *level* scopes — can change over time, a
difficulty "level" recorded long ago may not mean the same thing today. This document pins down what each
étude (and each of its levels) actually *was* at every version, so old data stays interpretable.

## How `Etude.version` works

- `Etude.version` is an optional field on each étude in **`src/questions/etudes.ts`** (typed in
  `src/contracts.ts`). It **defaults to `1`** when omitted.
- **Bump it whenever an étude's questions or difficulty change** — new question material, changed level
  scopes, changed distractors, changed timing, etc.
- The active version is recorded alongside each answered question, so historical accuracy/practice data
  can be read against the definition that was live at the time.

**Every étude is currently version 1.** (No `version` is set in `src/questions/etudes.ts`, so all default
to `1`.)

All questions are generated deterministically (no RNG — SRS ids must stay stable) in
**`src/questions/generators.ts`**; explanations come from `src/questions/explanations.ts`. The 12 keys
live in `src/theory/keys.ts` (circle-of-fifths order from C): C, G, D, A, E, B, F♯, F, B♭, E♭, A♭, D♭,
each with its relative minor.

Sudden-death answer timers are applied per **category** in `src/components/ReviewSession.tsx`
(`TIMED_LIMITS`); a question may override with its own `timeLimitMs`. Categories absent from that map are
untimed.

## No. 1 — Relative Minors (`relative-minors`) — current version: 1

### v1

- **Question family:** Relationship recall — "What is the relative minor of *X* major?", one question per
  key (12 total). Generated by `relativeMinorQuestions()` in `src/questions/generators.ts`.
- **Levels:** none (no `levels`; single undifferentiated set).
- **Distractors:** the relative-minor names of every *other* key (the answer plus three other minor
  names; `buildQuestion` sorts choices and keeps the first three distinct distractors).
- **Audio:** each minor-name choice plays its tonic minor triad (hover-to-play).
- **Reveal:** highlights the major/relative-minor pair on the **circle of fifths** (`q.circle`).
- **Timing:** category `Relative minor` — **5 s** sudden-death (`TIMED_LIMITS` in `ReviewSession.tsx`).

## No. 2 — Scales (`scales`) — current version: 2

### v2 — 2026-06-06: four ABRSM bands; add major scales + Greek modes

- **Question family (expanded):** now spells **major** scales too, not just the 3 minor forms, and the
  **Greek modes** at Expert. Generated by the rewritten `scaleSpellingQuestions()` (`SCALE_KINDS` ×
  `SCALE_LEVEL_ACCIDENTALS`); new mode spellings (`lydianScale`/`mixolydianScale`/`locrianScale`) added to
  `src/theory/scales.ts`.
- **Levels** (`['Easy','Medium','Hard','Expert']`): cumulative by key-signature accidentals (the Chords
  étude's `accidentalCount`), tracking ABRSM grade bands. Each level is its own SRS set via
  **level-prefixed ids** (`scale-notes:L{n}:{tonic}:{kind}`).
  - **Easy (L1):** keys ≤2 accidentals (≈ grades 1–2: C G D F B♭ + relative minors A E B D G) — major +
    natural/harmonic/melodic minor. 5 keys × 4 = **20**.
  - **Medium (L2):** ≤4 accidentals (≈ grades 3–4: adds A E E♭ A♭) — same 4 flavours. 9 × 4 = **36**.
  - **Hard (L3):** all 12 keys (grade 5+) — same 4 flavours. 12 × 4 = **48**.
  - **Expert (L4):** all 12 keys **plus the Greek modes** — Dorian, Phrygian, Lydian, Mixolydian, Locrian
    on each major tonic (skipping any (mode, tonic) needing a double accidental — drops Locrian on
    D♭/A♭/E♭ and Phrygian on D♭/A♭). 48 base + 55 modes = **103**. Total **207**.
- **Distractors:** unchanged principle — all options start on the **same tonic**; candidates are every
  other flavour on that tonic, rotated deterministically (`keyIndex + kindIndex + level`).
- **Reveal:** major + the 3 minor forms light the keyboard with RH/LH fingerings (`majorFingering` /
  `fingering`); the modes light the keys without finger numbers (no verified modal fingering).
- **SRS reset:** every id changed (gained `L{n}` and major/modes are new), so v1 Scales progress resets —
  expected on a content-version bump.

### v1

- **Question family:** Scale spelling — "What are the notes of the *X* natural / harmonic / melodic minor
  scale?", one question per (key, scale type) = 12 keys × 3 forms = 36. Generated by
  `scaleSpellingQuestions()` in `src/questions/generators.ts`; spellings computed in `src/theory/scales.ts`.
- **Levels:** none.
- **Distractors:** all options start on the **same tonic** so the first note never reveals the answer.
  Candidates are the two sibling minor forms plus three other same-tonic scales — the parallel **major**,
  **Dorian**, and **Phrygian**. The mix is varied deterministically per question (alternating "2 siblings
  + 1 other" vs "1 sibling + 2 others", rotating which appear), keyed by `keyIndex + typeIndex`.
- **Audio:** each scale choice plays ascending (hover-to-play).
- **Reveal:** lights the answer scale on the piano keyboard, each key labelled with RH over LH fingerings
  (from `src/theory/fingerings.ts`; the same finger sequence is shared across the three minor forms).
- **Timing:** untimed (no `Scale spelling` entry in `TIMED_LIMITS`).

## No. 4 — Key Signatures (`key-signatures`) — current version: 1

### v1

- **Question family:** Key signatures — "What notes are sharpened or flattened in *X* major/minor?",
  one question per (key, level). Generated by `keySignatureQuestions()` in `src/questions/generators.ts`.
- **Key scope:** the **15 standard major keys** across the circle of fifths (7♯ C♯ … 7♭ C♭, including the
  enharmonic pairs C♯/D♭, F♯/G♭, B/C♭) **+ their 15 relative minors**. Minor keys use the **natural
  minor** (= the key signature). No double accidentals occur in this scope.
- **Levels** (`['Easy','Medium','Hard','Expert']`, `SIG_LEVEL_ACCIDENTALS = [2,4,6,7]`): cumulative by
  key-signature accidentals, scaling like the Scales étude. Each level is its own SRS set via
  level-prefixed ids (`key-sig:L{n}:{tonic}:{mode}`).
  - **Easy (L1) ≤2:** C, G, D, F, B♭ (+ relative minors). 10 keys.
  - **Medium (L2) ≤4:** adds A, E, E♭, A♭. 18 keys.
  - **Hard (L3) ≤6:** adds B, F♯, D♭, G♭. 26 keys.
  - **Expert (L4) ≤7:** adds C♯, C♭ major and A♯, A♭ minor — the seven-accidental keys. 30 keys.
  - Totals: 10+18+26+30 = **84** questions.
- **Choices:** the accidental set in signature order ("F♯, C♯, G♯", or "None"). Distractors force the
  exact count *and* sharp-vs-flat: one fewer / one more of the same sign, plus the same count of the
  opposite sign (all valid prefixes of the sharp/flat order).
- **Reveal:** a treble staff shows the key signature and **only the sharpened/flattened notes** (one
  notehead per accidental, under the signature, each voiced as close to middle C as possible but never
  below it), and the keyboard highlights those same keys, each
  **labelled with its note name** (so a white-key enharmonic like E♯ on the F key is unambiguous). C
  major / A minor have no accidentals → **no staff and no keyboard**. The staff is centred, like the
  keyboard.
- **Timing:** **15 s sudden-death** (`'Key signature'` in `TIMED_LIMITS`).

## No. 5 — Chords by Degree (`chords`) — current version: 2

  - **Medium (L2):** keys with ≤3 accidentals.
  - **Hard (L3):** all 12 keys.
- **Distractors:** a **same-root / different-quality** chord (so the root alone never reveals it), plus
  the **same degree in other keys of the same mode** (so the quality alone never reveals it).
- **Audio:** each chord choice plays as a block (hover-to-play).
- **Reveal:** lights the answer chord (root position) on the keyboard with RH/LH fingerings.
- **Timing:** category `Diatonic chord` — **5 s** sudden-death.

### v2 — 2026-06-02: four ABRSM bands (add Expert)

## No. 6 — Chord Recognition (`chord-recognition`) — current version: 2

### v1

- **Question family:** Read a diatonic chord rendered on a **staff** (under its key signature) and name
  it as a chord symbol, with slash notation for inversions — "In *key*, name the chord shown." Both modes,
  all seven degrees. Minor uses harmonic forms at III/V/vii° (so augmented III+, dominant V, diminished
  vii° appear). Generated by `chordRecognitionQuestions()` in `src/questions/generators.ts`. Size,
  inversion, and clef (treble/bass) are chosen deterministically from a running index for a stable,
  well-mixed bank; an "unclean" ninth is demoted to its seventh.
- **Levels** (`['Easy','Medium','Hard']`, `REC_LEVELS`): scale chord complexity **and** key range:
  - **Easy (L1):** triads only, no inversions, keys with ≤1 accidental.
  - **Medium (L2):** triads + sevenths, inversions allowed, keys with ≤3 accidentals.
  - **Hard (L3):** triads + sevenths + ninths, inversions allowed, all 12 keys.
- **Distractors:** prioritized to vary inversion / root / quality — the other inversions of the same chord
  (when inversions are on), the **same degree/size in neighbour keys** (different roots), and a
  **same-root / alternate-quality** symbol. Easy (no inversions) keeps root-position symbols only.
- **Audio:** each choice sounds its own chord as a block, voiced in a comfortable register (hover-to-play).
- **Reveal:** the chord is shown on the staff as the *question* itself (`q.notation`, not on-reveal).
- **Timing:** category `Chord recognition` — **10 s** sudden-death; inversion questions override to
  **15 s** (`q.timeLimitMs`, +5 s to re-stack the notes in thirds).

### v2 — 2026-06-02: four ABRSM bands (add Expert; ninths moved up)

- **Levels** (`['Easy','Medium','Hard','Expert']`, `REC_LEVELS`): ABRSM-aligned ladder — root triads →
  inversions → sevenths → ninths. **Ninths now appear only in Expert** (Hard was too hard).
  - **Easy (L1):** triads, root position, keys ≤3 accidentals.
  - **Medium (L2):** triads **with inversions**, all keys.
  - **Hard (L3):** + **sevenths**, inversions, all keys.
  - **Expert (L4):** + **ninths**, inversions, all keys, **tighter clock** (8 s base, +4 s for inversions).
- Per-level v1 progress resets (level scope shifted).

## No. 7 — Spell the Chord (`chord-spelling`) — current version: 2

### v1

- **Question family:** The **inverse of Chord Recognition** — show a chord **symbol** and pick its notes
  ("Spell the chord *symbol*."). The symbols are the diatonic chords of every key (so spellings are always
  correct, one letter per chord tone), both modes, all seven degrees. Generated by
  `chordSpellingQuestions()` in `src/questions/generators.ts`; size is chosen deterministically from a
  running index, and an "unclean" ninth is demoted to its seventh. No inversions (the answer is the set
  of chord tones, listed root-position ascending).
- **Levels** (`['Easy','Medium','Hard']`, `SPELL_LEVELS`): scale chord complexity **and** key range, like
  Chord Recognition but without inversions:
  - **Easy (L1):** triads only, keys with ≤1 accidental.
  - **Medium (L2):** triads + sevenths, keys with ≤3 accidentals.
  - **Hard (L3):** triads + sevenths + ninths, all 12 keys.
- **Distractors:** **same root, different quality** (the symbol already gives the root, so a different
  first note would be a giveaway). Triads offer the other triad qualities; sevenths the other seventh
  qualities; ninths the other clean ninth types (9 / maj9 / m9 / m(maj9)). Spelled via `spellChord`; any
  out-of-range spelling is skipped.
- **Audio:** each choice (a note set) sounds as a block chord, voiced ascending from C4 (hover-to-play).
- **Reveal:** the chord on a **staff** under its **own tonic-key signature** (major key of the root for a
  major 3rd, minor key for a minor 3rd, so the root names the key and the rest of the chord prints as
  accidentals; falls back to no signature when that key is unreal, e.g. D♯ major) **beside** a piano
  keyboard with RH/LH fingerings (`q.notation` on-reveal + `q.keyboard`).
- **Timing:** category `Chord spelling` — **untimed** (a deliberate reading/reveal exercise).

### v2 — 2026-06-02: four ABRSM bands (add Expert)

- **Levels** (`['Easy','Medium','Hard','Expert']`, `SPELL_LEVELS`): chord size × key range, with the full
  key range held back to Expert so every band is distinct.
  - **Easy (L1):** triads, keys ≤1.
  - **Medium (L2):** + sevenths, keys ≤3.
  - **Hard (L3):** + ninths, keys ≤5.
  - **Expert (L4):** + ninths, all twelve keys.

## No. 13 — Tap the Rhythm (`rhythm-tap`) — current version: 4

### v1 — 2026-06-02

- **Question family:** the performance counterpart of Rhythm Dictation. Show a one-bar rhythm as
  notation; after a one-bar count-in (a metronome click on **every felt beat**, continuing under the
  bar), the student **taps and holds** the rhythm with Space or by pressing the staff. Interactive
  (non-MC), graded pass/fail to SRS from a timing-accuracy %. One uniform wooden metronome click runs
  throughout — count-in and exercise sound identical, with only a slight accent on the first beat of each
  measure; the count-in counts the felt beats **1·2·3·4** (as many as the metre has) and the downbeat where tapping begins gets a
  **green** flash of the staff (the colour cue).
- **Patterns / levels / metres:** reuses Rhythm Dictation's `RHYTHM_LEVELS` verbatim (Easy/Medium/Hard/
  Expert; tempi 76/100/138/152; the same per-level metre cascade), with the same `audibleSignature`
  dedupe — one tap exercise per unique-sounding pattern (183 total, mirroring rhythm-dictation). Spec
  lives on `q.tapAlong` (`{ meter, tempo, pattern }`); ids are `rhythm-tap:L<level>:<metre>:<rhythmKey>`.
- **Grading (`scoreTaps` in `src/rhythm.ts`):** each struck note (rests/tied-continuations excluded — see
  `onsets`) expects one tap. **Perfect window** ≈ `clamp(133 + 67·noteBeats, 150, 200)` ms — ~200 ms for a
  quarter, tightening to 150 ms for sixteenths (smaller window for faster notes; forgiving overall). Score
  decays linearly to zero at `min(3× perfect, 0.45× gap-to-neighbour)`; a missed onset scores 0 and each
  **extra** tap costs half an onset. A matched tap must also be **held ≥ 70 %** (`HOLD_MIN`) of the note's
  sounding length (ties included) — a clipped tap scores 0 and is flagged *too short*. Accuracy = mean
  per-onset score (minus extras), 0–100; **≥ 80 % passes**.
- **Feedback:** the results screen re-renders the notation with each note coloured by how it was hit
  (viridian on-beat / gold off-but-counted / vermilion missed, via `RhythmStaff`'s `eventColors`), plus a

## Updating this file

This file is **append-only**. When you change an étude's questions or difficulty:

1. **Bump its `version`** in `src/questions/etudes.ts` (e.g. add/raise `version: 2` on that étude entry).
2. **Append a new subsection** under that étude here:

   ```
   ### vN — <YYYY-MM-DD>: <one-line summary of what changed>
   ```

   Describe the new version the same way the existing subsections do (question family, level scopes,
   distractors, timing).

3. **Leave all prior `### vN` subsections intact.** Old practice/CSV data was recorded against those
   definitions and must stay interpretable — never edit or delete a past version, only add the next one.
4. Update the étude's heading "current version: N" to match the bump.
